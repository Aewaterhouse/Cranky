# Code map

## Root
- `PLAN.md` design and phases; `AGENTS.md` working rules; `README.md` setup; `Dockerfile` production image (client build + server).
- `scripts/run.sh` build client and start server on :8000; `scripts/selfsigned.sh` self-signed certs for LAN HTTPS.
- `scripts/routes/build_routes.py` builds bundled route packs from OpenStreetMap and SRTM; `terrain.py` SRTM tile reader and the height grid around a route; `features.py` land cover, side roads, buildings and landmarks from OpenStreetMap; `gpx.py` routes cut from a recorded ride; `fit.py` minimal FIT reader for course files; `net.py` cached fetch; `routes.json` route definitions (waypoints, published figures); `test_build_routes.py` its tests (`cd server && uv run pytest ../scripts/routes`).
- `content/routes/index.json` route cards; `content/routes/<id>.json` one pack per bundled route.
- `docs/protocol.md` wire protocol; `docs/road-games.md` how to add a game on top of the group ride; `content/tests/road-vectors.json` physics and route vectors both test suites run (generated, never read by hand); `docs/testing.md` manual tests; `docs/status.md` state; `docs/decisions.md` invented mechanics; `docs/freeride-plan.md` free ride 3D world plan; `docs/ride-notes-plan.md` checklist from the first real rides (current priority); `docs/hud-notes.md` HUD conventions from Zwift, TrainerRoad and MyWhoosh and the layout spec drawn from them; `docs/map.md` this file.
- `content/workouts/*.json` plans; `content/schema/workout.schema.json` plan schema; `content/cosmetics.json` shop catalogue.

### scene/route/ (the free-ride road world; files without three.js are unit-tested)

- `funSigns.ts` where the funny signs and the chalk go and what they say (no three.js); `funSignGeo.ts` builds the boards and lays the chalk on the road.
- `lifePlan.ts` which mob, flock, crossing animal, magpie or oncoming vehicle is where, seeded, chunk by chunk (no three.js); `lifeGeo.ts` animal and vehicle shapes; `life.ts` pooled instanced animals and traffic and how they move each frame.

- `feelVis.ts` tunables for the camera extras and rider poses (`VIS.route.feel`); `riderPose.ts` which pose a rider on the road wants (standing, coasting, tuck, cheer), lean, and the camera's shake, roll and view maths (no three.js).
